# Аудит сайта с каталогом

Задача — дать заказчику и аналитику ответ на вопрос «что из текущего сайта сохранить, что улучшить, что переделать, что добавить» и собрать требования к новому сайту. Оценка привязана к целям заказчика, поэтому без файла контекста аудит превращается в общий список замечаний — его не делаем.

Аргументы: `$ARGUMENTS`. Первый — файл контекста, остальные — сайты. Если сайты не переданы, берите их из контекста.

## Файлы skill — когда читать

| Файл | Когда |
|---|---|
| `references/checklist.md` | Перед сбором данных: критерии, ★, чем проверять |
| `references/scoring.md` | Перед оценкой: итоги ✓ / ◐ / ✗, светофор, вердикты |
| `references/report-template.md` | Перед написанием отчёта |
| `references/pitfalls.md` | Перед работой в браузере и при любой странности: заглушки, зависшие скриншоты, кириллица в URL, экономия токенов |
| `scripts/seo_check.mjs` | Запускать, не читать: технические SEO-проверки одного сайта |

Пути — от папки skill: `${CLAUDE_SKILL_DIR}`.

## Порядок работы

Скопируйте список в ответ и отмечайте шаги:

```
- [ ] 1. Контекст прочитан, сайты и роли понятны
- [ ] 2. Технические данные: seo_check по каждому сайту
- [ ] 3. Браузер: набор страниц, десктоп и мобильный
- [ ] 4. Оценка по критериям, светофор
- [ ] 5. Отчёт по шаблону
- [ ] 6. Самопроверка пройдена
- [ ] 7. Итог пользователю
```

### 1. Контекст

Прочитайте файл контекста. Из него нужны: цели заказчика и какой блок чек-листа какой цели соответствует; сайты и их роли (`текущий`, `старый`, `эталон`); сегменты клиентов; примеры разделов каталога; куда сохранить отчёт и скриншоты; запросы для ручной GEO-проверки.

Если файла нет или в нём не хватает целей, ролей или пути для отчёта — спросите пользователя и не начинайте сбор: без этого не из чего считать светофор.

Если отчёт уже существует, дополните его колонкой нового сайта, не переписывая проверенное.

### 2. Технические данные — первый проход

Для каждого сайта:

```bash
node "${CLAUDE_SKILL_DIR}/scripts/seo_check.mjs" <сайт> [--old <старый-домен>] --out <tmp>/seo_<домен>.json
```

- `--old` — для текущего сайта, если в контексте есть старый домен: проверит редиректы (2.2) и состояние старого сайта.
- Без `--pages` скрипт берёт главную и выборку из sitemap — обычно карточки. Разделы, контакты и другие служебные страницы он может не увидеть; их добавите во втором проходе (шаг 3).
- JSON кладите во временную папку (scratchpad), не в проект. Сводку из stdout переносите в приложение отчёта.

Скрипт закрывает большую часть блока 2. Если он пишет «ВНИМАНИЕ … заглушка», данные по этим страницам недостоверны — см. `pitfalls.md`.

### 3. Браузер (Playwright MCP)

Набор страниц на сайт, в этом порядке: **листинг** (первым — чтобы замерить скорость без кэша) → главная → 1 карточка в браузере + ещё 2–4 карточки из других категорий через `fetch` из страницы → корзина или форма заявки → контакты. Десктоп `1440×900`, затем мобильный `390×844` для главной, листинга и карточки, с раскрытием мобильного меню.

- Открывайте страницы `browser_navigate`, данные берите `browser_evaluate` (готовые выражения и рецепт для нескольких карточек — в `pitfalls.md`). Полный снимок страницы не читайте: он дорогой и почти всегда не нужен.
- Фильтры проверяйте действием: примените два фильтра, убедитесь, что список изменился, сбросьте.
- Скриншоты — только ключевые, на которые сошлётесь в отчёте: `browser_take_screenshot` с `filename` в папку из контекста, имя `<сайт>_<NN>_<страница>_<устройство>.png`.
- Формы не отправляйте, заказы не оформляйте: можно открыть форму и посмотреть поля.
- Закройте браузер (`browser_close`), когда закончите.

**Второй проход скрипта:** перезапустите `seo_check.mjs` с `--pages` — полные URL листинга, 2–3 разделов и контактов через запятую (короткие пути Git Bash искажает). Так title, H1 и дубли title проверятся и на разделах.

### 4. Оценка

По `scoring.md`: у каждого критерия итог ✓ / ◐ / ✗ / ❓ / н/п / не проверено, короткая находка и вердикт. У ◐ обязательно объяснение, за что половина балла. Для сайта-эталона вместо вердикта — «что взять».

Отличайте факт от догадки: всё, что не видели сами, помечайте *(гипотеза)*; что можно узнать только у заказчика — *(вопрос заказчику)*.

### 5. Отчёт

Строго по `report-template.md`: в таблицах номер критерия всегда вместе с коротким названием — отчёт должен читаться без чек-листа. Если в прогоне один сайт или нет эталона — уберите лишние колонки и раздел «Сравнение с эталоном», не оставляйте заглушек.

Находки, которым нет критерия (например, старый сайт живёт отдельно, страница 404 без навигации), не теряйте: в «Главное», если важно для заказчика, иначе — в «Прочие наблюдения» отчёта.

### 6. Самопроверка

Перед сохранением пройдите по пунктам и исправьте найденное:

- у каждого критерия каждого сайта есть итог; у каждого ◐ — объяснение;
- баллы и цвета в светофоре пересчитаны по `scoring.md` (★ с ✗ — красный, ★ с ◐ — не выше жёлтого);
- вердикт стоит у каждого ✓ / ◐ / ✗; у ❓, н/п и «не проверено» — «—». Сумма вердиктов в «Главном» = число критериев с ✓ / ◐ / ✗ и совпадает с таблицами;
- ⚡ стоит только у пунктов из перечня в `scoring.md`;
- все упомянутые скриншоты существуют;
- в «Ограничениях проверки» перечислено, что не проверено и почему.

### 7. Итог пользователю

Коротко: где отчёт, 3–5 главных находок, что не удалось проверить, что проверить вручную (GEO-запросы, Яндекс Вебмастер, Карты).
